# Repository Review: 2026-09-27

Scope: runtime, state machine, workers, adapters, evidence collection, learning,
replay, CLI, packaging, tests, roadmap, and the unfinished benchmark implementation.
The existing 52 tests passed before changes. This is an engineering review, not
an exhaustive security audit or evidence that live agents improve task outcomes.

## Findings And Resolution

Line references below describe the reviewed 1.10.0 source and may shift as fixes land.

1. **Resolved in 1.11.0: Skipped workers could produce an ordinary runtime PASS.**
   `moregan/runtime.py:614` initializes status to pass and changes it only for
   failures. A fresh repository with no provider and `--no-checks` still completes
   successfully. Existing tests explicitly assert this behavior. Add an incomplete
   terminal outcome, require executed gates for completion, and propagate the
   result to CLI exit status and learning. The new benchmark runner independently
   guards against this and does not count skipped stages as success.
   Resolution: added an incomplete terminal state, nonzero run exit, incomplete
   stage reporting, and unverified learning observations. Empty and entirely
   skipped deterministic gates also cannot pass. Verified complete and incomplete
   low/medium/high/critical routes and fail-over-incomplete precedence.

2. **Resolved in 1.11.0: Provider output could crash execution or silently lose findings.**
   `moregan/workers.py:233` assumes a dictionary, directly coerces numeric fields,
   and filters malformed finding collections. The provider wrapper has a separate,
   inconsistent normalization path at `moregan/agent_worker.py:152`. Introduce one
   strict boundary validator and structured failures for malformed fields, missing
   executables, and timeout output. Test arrays, nulls, non-finite confidence,
   negative line numbers, contradictory verdicts, and invalid collections.
   Resolution: both adapters now share exact JSON decoding and strict field
   validation without coercion or filtering. MoreGAN owns execution metadata.
   Launch, encoding, prompt, and timeout errors produce structured failures;
   timeout bytes serialize safely. Added malformed-data tests, actual subprocess
   timeouts, and end-to-end scaffolded Codex/Claude adapter tests.

3. **Resolved in 1.12.0: Risk was not reassessed after generation.**
   `moregan/runtime.py:572` calls the classifier only at intake. A request initially
   routed low remains low when its generator edits authentication or migration
   files. Add reassessment after each generator attempt, monotonic escalation, and
   a documented policy for newly required pre-generation reviews. Existing diff
   tests cover changes already present before execution, not this scenario.
   Resolution: reassess after every returned generator attempt, retain the highest
   risk, and execute newly required reviews before verification. Fixed-baseline
   Git evidence includes generated commits and untracked paths. Catch-up review
   failures use bounded remediation; missing reviewers remain incomplete. Tests
   cover actual filesystem changes, routing, retention, traces and provider context.

4. **Resolved for deterministic capture/deadlines in 1.13.0; platform limits remain.**
   `moregan/runtime.py:484` runs subprocesses without a timeout and buffers all
   output. A hung test can prevent completion indefinitely. Add configurable
   timeouts, bounded logs, and process cleanup, with structured timeout evidence.
   Resolution: per-command validated deadlines and continuously drained bounded
   output tails; timeout, launch, capture and cleanup failures become evidence.
   POSIX process groups are killed on exit, timeout or interruption. Builtin Python
   file discovery is also bounded and fails on truncated listings. Added 20 tests
   for noisy/hung checks, child cleanup, config validation, evidence and remediation.
   Windows only cleans up the direct child; escaped POSIX sessions are not contained.
   Provider capture is still separate and unbounded. See [execution limits](tool-execution.md).

5. **Resolved in 1.12.0: Replay substituted the latest stage for earlier attempts.**
   `moregan/replay.py:136` loads `<stage>.json` for every historical entry, so a
   failed attempt followed by a pass can appear as multiple copies of the final
   pass. Load attempt-specific files or use the embedded stage result, and add a
   fail-then-pass replay regression test.
   Resolution: load the matching attempt file, falling back to the embedded stage
   result. Regression tests preserve failed-then-passed reviews and distinct risk
   assessments, including when an attempt file is missing.

6. **P2: No-write snapshots are not a process sandbox and are not cleaned up.**
   `moregan/workers.py:348` creates persistent temporary copies. Repository mode
   compares git status text, which does not detect changing an already dirty file
   while preserving its status. Clean up snapshots reliably and use file-content
   evidence where no-write behavior is promised. Strong containment requires a
   separate OS-level execution boundary.

7. **P2: Published support and release checks need validation.**
   The package advertises Python 3.8, but `install.py:286` uses `str.removesuffix`,
   which is unavailable there. The publishing workflow builds and publishes without
   running tests. Decide and test the supported Python range and add CI/release
   gates before enabling a release. PyPI publication remains paused.

## Benchmark Draft Findings Addressed

- Replaced unrelated prompts executed in the user's checkout with six executable
  fixtures in independent temporary workspaces.
- Replaced runtime-PASS-as-success with independent acceptance checks and explicit
  unmeasured states for skips and provider/verification errors.
- Added actual generator-only baseline execution using the same fixtures.
- Required matching task definitions and task sets for paired comparisons.
- Excluded missing observations from measured pairs and retained null metric totals.
- Added unique run ids, validation before execution, task checkpoints, persisted
  evidence, CLI coverage, and fixture tests that check broken and repaired versions.

## Next Development Order

1. Clean up worker snapshots and strengthen no-write enforcement.
2. Bound provider output and supervise worker processes; add Windows child-tree containment.
3. Add release CI and test the declared Python/OS support matrix.
4. Expand benchmarks, collect actual provider cost/usage, and perform repeated
   paired agent runs before competitive generators or effectiveness claims.

The architecture is worth continuing. The current release remains an alpha;
passing unit tests should not be described as production readiness.
