# MoreGAN 1.16.0

## Reliable Distribution (M1)

- Python requirement is now 3.10+. CI covers Python 3.10-3.14 on Linux and macOS.
- Added Windows wheel/skill installation and simulated-provider smoke checks on
  Python 3.10 and 3.14. Windows process-tree containment remains unsupported.
- Shared CI builds wheel/sdist, checks metadata and README rendering, runs the
  regression matrix and exercises the exact wheel outside the checkout.
- Release tags must match package, runtime, installer, skill and lock versions.
  Publishing rejects branch dispatches, drafts, prereleases and checkout drift.
- Version-tag pushes run quality gates, create a GitHub release and publish the
  same tested distributions through PyPI Trusted Publishing. No rebuild occurs
  in the publishing job. Documentation-only commits need not create a release.
- Setup scripts check the supported Python floor and show the runtime version.
- New worker templates use the active Python interpreter, avoiding a different
  `python3` installation or a missing Windows alias. Regenerate templates when
  moving the environment; existing configs are not rewritten automatically.
- Fixed false checkout-integrity failures from Windows stat/fstat timestamp
  semantics. Both pathname and open-handle observations are checked for stability;
  content hashing uses binary mode, preserving newline differences.

## Since The Previous PyPI Release (1.5.0)

This release also delivers the intervening GitHub work: context packs, empirical
learning observations, diff-aware routing and escalation, stack presets including
Java/Spring Boot, the benchmark foundation, truthful incomplete outcomes, strict
provider contracts, bounded execution, checkout-integrity checks and run replay
fixes. See ROADMAP.md for the original ten-item tracker.

## Remaining Limits

Provider setup still requires a custom bridge. Turnkey native providers and skill
parity are M2-M3, not shipped in this release. No automatic rollback, competing
generators, OS sandbox or measured live-agent benefit is claimed. Required project
checks must be configured deliberately. Updating from 1.5.0 does not overwrite
existing repository configuration or automatically replace installed skills.
